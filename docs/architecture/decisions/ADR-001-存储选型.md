# ADR-001：存储选型 — SQLite（WAL）＋ 文件产物区

- 状态：已接受
- 日期：2026-10-21
- 关联：ADR-000（架构总览）；规范 §14.3（核心数据实体）、§18（可观测性与可恢复性）

## 背景

平台需持久化 20+ 类实体（任务、审查、测试、缺陷、审批、审计、用量），并保存大量产物（代码 diff、测试报告、构建产物、交付包）。最终形态是 Windows 本地桌面应用，要求零运维、可备份、崩溃后可恢复（P1-4）。

## 决策

1. **结构化数据：SQLite，启用 WAL 模式**。存全部实体表（含 ID/时间/状态/版本/审计字段，规范 §14.3）与 `runtime/state/` 下的工作流状态。
2. **大对象与证据：文件产物区** `runtime/artifacts/`（按项目/任务分目录），数据库只存引用路径与校验信息（哈希、大小）。
3. **检查点**：`runtime/checkpoints/` 与状态库配合，支持杀进程后恢复（P1-4 验收）。
4. 迁移：内置版本化 schema 迁移表；变更走迁移脚本，不裸改表。

## 备选方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. SQLite(WAL)＋文件产物区 | 零运维、单文件可备份、事务完整、桌面应用标配 | 并发写入有限（WAL 下读写不互斥） | **采用**（第一版单项目串行，D7，够用） |
| B. 纯 JSON 文件存储 | 实现简单 | 无事务、崩溃易损坏、查询弱，不满足审计与恢复要求 | 拒绝 |
| C. PostgreSQL/MySQL | 并发与功能强 | 用户需装数据库服务，违背"本地桌面、零运维"定位 | 拒绝（架构上经仓储层隔离，未来远程模式可再评估） |
| D. 嵌入式 KV（LMDB 等） | 快 | 无结构化查询/关系约束，实体关系管理成本高 | 拒绝 |

## 结论

- Phase 1（P1-4）实现仓储层＋WAL＋检查点；崩溃恢复为阶段验收项。
- 产物文件一律带校验信息入库；状态转移证据（命令/退出码/版本）随实体存储（规范 §7.4）。
- 本地数据库文件与产物不入 Git（.gitignore 已排除 runtime/ 内容）。
