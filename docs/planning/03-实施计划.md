## 2. 总体策略

1. **模拟先行**：Phase 1–2 全部用模拟模型适配器验证工作流、状态机和门禁，不依赖真实模型、不产生模型费用。
2. **门禁引擎优先**：ESEE（工程标准执行引擎）独立成阶段并提前，因为它是乙强制指令的第 3 条优先级，也是防止"AI 谎报通过"的技术根基。
3. **单语言闭环先于扩展**：先把 Python 一条端到端链路做实（生成→审查→测试→修复→构建→交付），再扩展语言和桌面 UI。
4. **每阶段必须可运行、有证据**：每个 Phase 有明确门禁，未通过不进入下一阶段；阶段结束输出证据报告。
5. **桌面 UI 与打包靠后**：开发期用 CLI 驱动一切，产品形态（Windows 桌面安装包）在核心链路可靠后实现。

## 5. 风险清单（Top 10）

| # | 风险 | 影响 | 缓解措施 |
|---|---|---|---|
| R1 | 模型输出不稳定导致流程卡死或产物不合格 | 任务阻塞、成本浪费 | 模拟适配器先行；重试上限＋预算控制＋根因分析；超限转 BLOCKED 转人工 |
| R2 | 范围过大导致烂尾 | 平台不可用 | 严格按 Phase 门禁推进；每阶段必须有可运行成果；先闭环后扩展 |
| R3 | Windows 环境工具差异（路径/编码/权限/Shell） | 检查与构建失败 | 环境自检脚本；语言适配器隔离平台差异；CI 覆盖 Windows |
| R4 | 外部 Skill 供应链风险（恶意指令/许可证） | 安全事故 | 接入流水线强制审查、隔离试用、版本固定；指令性内容不高于平台策略 |
| R5 | 长任务超出模型上下文 | 产出劣化 | 产物化交接（不靠聊天传话）；知识按需检索；任务粒度控制 |
| R6 | 模型调用成本失控 | 预算超支 | 用量记录＋预算门禁；模拟模式承担大部分开发验证 |
| R7 | AI 自报状态与实际不符 | 假进度、假通过 | 状态转移只由控制器依据工具证据触发（P1-2/P3-4） |
| R8 | 测试/命令污染用户机器 | 用户损失 | 工作区白名单＋命令白名单＋超时＋危险操作审批 |
| R9 | 需求访谈体验差（问题过多/术语化） | 用户放弃 | 一次一问＋选项化＋简明摘要确认 |
| R10 | 两份源规范执行不一致 | 返工 | 以合并版为唯一基准；规范配置化注入每个任务 |

## 6. 工作方式约束

1. **每阶段结束输出证据报告**：完成内容、修改文件、执行过的命令、测试证据、失败项、已知限制、下一阶段计划。
2. **红线（违反即阶段不通过）**：不伪造通过；不删测试/放宽断言换绿灯；不无限重试；不越权访问；不把未验证标为通过；不在需求未批准时编码。
3. **契约先行**：P1 冻结的 JSON Schema 是 P2/P3 并行的前提；上游契约变更必须触发受影响任务重验。
4. **决策变更走 ADR**：D1–D10 或架构决策变化时新增/修订 ADR，不口头变更。
5. **后续任务登记**：本计划未覆盖的规范条款（如 Phase 8 后的持续优化、更多语言）登记入 `docs/backlog.md`，不静默丢弃。
